# راهنمای API صرافی LBank

هرچه در این سند آمده با فراخوانی واقعی API آزمایش شده است، نه فقط از روی مستندات. جاهایی که رفتار واقعی با مستندات رسمی فرق داشت، صریحاً علامت‌گذاری شده‌اند.

---

## نشانی‌ها

| کاربرد | نشانی |
|---|---|
| REST (اصلی) | `https://api.lbkex.com` |
| REST (جایگزین) | `https://www.lbkex.net` |
| WebSocket نسخه ۲ | `wss://www.lbkex.net/ws/V2/` |

همه مسیرهای REST با `/v2/` شروع و با `.do` تمام می‌شوند.

---

## قالب نماد

</div>

```
داخل برنامه:   BTC/USDT
در LBank:      btc_usdt        (حروف کوچک، جداکننده زیرخط)
```

<div dir="rtl">

تبدیل در `LBankProvider.to_exchange_symbol` و `from_exchange_symbol` انجام می‌شود. هیچ جای دیگری از برنامه نباید قالب LBank را بشناسد.

## تشخیص موفقیت پاسخ

این مهم‌ترین نکته کار با LBank است: **خطاها با کد HTTP ۲۰۰ برمی‌گردند.**

</div>

```json
{ "result": "true", "error_code": 0, "data": [ ... ] }     ← موفق
{ "result": "false", "error_code": 10008, "msg": "..." }   ← ناموفق
```

<div dir="rtl">

> ⚠ **دام واقعی:** فیلد `result` گاهی رشته `"true"` و گاهی مقدار بولی `true` است. بررسی باید هر دو را بپذیرد:

</div>

```python
success = payload.get("result") in ("true", True) and payload.get("error_code", 0) == 0
```

<div dir="rtl">

## نقاط پایانی عمومی

### زمان سرور

</div>

```
GET /v2/timestamp.do
→ { "result": "true", "data": 1757312400000 }     میلی‌ثانیه
```

<div dir="rtl">

از این برای بررسی سلامت اتصال استفاده می‌شود (`ping`).

### فهرست نمادها

</div>

```
GET /v2/currencyPairs.do
→ { "result": "true", "data": ["btc_usdt", "eth_usdt", ...] }
```

<div dir="rtl">

در زمان نگارش این سند حدود **۱۳۸۸ جفت‌ارز** برمی‌گرداند.

### دقت اعشار

</div>

```
GET /v2/accuracy.do
→ data: [{ "symbol": "btc_usdt", "quantityAccuracy": "4", "priceAccuracy": "2" }, ...]
```

<div dir="rtl">

برای گرد کردن درست قیمت‌ها در نمایش لازم است.

### تیکر ۲۴ ساعته

</div>

```
GET /v2/ticker/24hr.do?symbol=btc_usdt        یک نماد
GET /v2/ticker/24hr.do?symbol=all             همه نمادها (برای صفحه بازارها)

→ data: [{
    "symbol": "btc_usdt",
    "ticker": { "high": …, "low": …, "latest": …, "vol": …, "turnover": …, "change": … },
    "timestamp": 1757312400000
  }]
```

<div dir="rtl">

`change` همان درصد تغییر ۲۴ ساعته است.

### کندل‌ها (مهم‌ترین نقطه پایانی)

</div>

```
GET /v2/kline.do?symbol=btc_usdt&size=200&type=hour1&time=1757200000
```

<div dir="rtl">

| پارامتر | توضیح |
|---|---|
| `symbol` | نماد به قالب LBank |
| `size` | تعداد کندل، حداکثر **۲۰۰۰** (۳۰۰۰ خطای پارامتر می‌دهد) |
| `type` | نوع تایم‌فریم (جدول پایین) |
| `time` | زمان شروع بر حسب **ثانیه** (نه میلی‌ثانیه) |

> ⚠ **دام مهم و آزمایش‌شده:** پارامتر `size` تعداد کندل را **رو به جلو** از `time` می‌شمارد، نه رو به عقب. برای گرفتن ۲۰۰ کندل آخر باید `time` را روی `اکنون − ۲۰۰ × طول_کندل` بگذارید. در پیاده‌سازی برنامه، دو کندل حاشیه اضافه هم گرفته می‌شود تا کندل ناقص جاری مشکلی ایجاد نکند. **این حاشیه را حذف نکنید.**

پاسخ آرایه‌ای از آرایه‌هاست:

</div>

```json
[[1757200000, 78120.5, 78560.0, 77980.2, 78432.1, 145.32], ...]
   زمان(ثانیه)  باز     بالا     پایین    بسته      حجم
```

<div dir="rtl">

#### تایم‌فریم‌های پشتیبانی‌شده

| تایم‌فریم برنامه | کد LBank | وضعیت |
|---|---|---|
| `1m` | `minute1` | ✅ بومی |
| `3m` | — | ❌ **خطای ۱۰۰۰۰** → از `1m` تجمیع می‌شود |
| `5m` | `minute5` | ✅ بومی |
| `15m` | `minute15` | ✅ بومی |
| `30m` | `minute30` | ✅ بومی |
| `1h` | `hour1` | ✅ بومی |
| `2h` | — | ❌ **خطای ۱۰۰۰۰** → از `1h` تجمیع می‌شود |
| `4h` | `hour4` | ✅ بومی |
| `6h` | — | ❌ **خطای ۱۰۰۰۰** → از `1h` تجمیع می‌شود |
| `8h` | — | ❌ **خطای ۱۰۰۰۰** → از `4h` تجمیع می‌شود |
| `12h` | — | ❌ **خطای ۱۰۰۰۰** → از `4h` تجمیع می‌شود |
| `1d` | `day1` | ✅ بومی |
| `1w` | `week1` | ✅ بومی |

> مستندات رسمی LBank این تایم‌فریم‌ها را فهرست می‌کند، اما در عمل `minute3`, `hour2`, `hour6`, `hour8`, `hour12` خطای `error_code: 10000` می‌دهند. به همین دلیل در `LBANK_TIMEFRAME_MAP` نیامده‌اند و موتور تایم‌فریم آن‌ها را می‌سازد.

## WebSocket

### اتصال

</div>

```
wss://www.lbkex.net/ws/V2/
```

<div dir="rtl">

### اشتراک

</div>

```json
{"action": "subscribe", "subscribe": "tick",  "pair": "btc_usdt"}
{"action": "subscribe", "subscribe": "kbar",  "kbar": "1min", "pair": "btc_usdt"}
{"action": "subscribe", "subscribe": "depth", "depth": "10",  "pair": "btc_usdt"}
{"action": "subscribe", "subscribe": "trade", "pair": "btc_usdt"}
```

<div dir="rtl">

برای لغو اشتراک، `subscribe` را با `unsubscribe` جایگزین کنید.

### کدهای کندل در WebSocket

با REST فرق دارند: `1min`, `5min`, `15min`, `30min`, `1hr`, `4hr`, `day`, `week`.

### ضربان قلب (حیاتی)

سرور هر چند ثانیه پیام زیر را می‌فرستد:

</div>

```json
{"action": "ping", "ping": "0ca8f854-7ba7-4341-9d86-d3327e52804e"}
```

<div dir="rtl">

کلاینت **باید** با همان شناسه پاسخ دهد، وگرنه اتصال قطع می‌شود:

</div>

```json
{"action": "pong", "pong": "0ca8f854-7ba7-4341-9d86-d3327e52804e"}
```

<div dir="rtl">

> به همین دلیل در `websocket_client.py` مقدار `ping_interval=None` تنظیم شده است: ضربان قلب باید با پروتکل خود LBank مدیریت شود، نه با ping خودکار کتابخانه `websockets`.

### درخواست تک‌باره

بدون اشتراک دائمی هم می‌توان داده گرفت:

</div>

```json
{"action": "request", "request": "tick", "pair": "btc_usdt"}
```

<div dir="rtl">

### اتصال مجدد

پیاده‌سازی برنامه با قطع اتصال، با تأخیر نمایی دوباره وصل می‌شود و **همه اشتراک‌های قبلی را خودکار برقرار می‌کند**. اگر این کار انجام نشود، اتصال برقرار می‌ماند ولی هیچ داده‌ای نمی‌آید — بدترین حالت ممکن، چون کاربر فکر می‌کند قیمت‌ها زنده‌اند.

## API خصوصی

نسخه ۱ برنامه معامله انجام نمی‌دهد، اما ساختار امضا برای توسعه آینده اینجاست.

همه درخواست‌های خصوصی **POST** هستند و به این پارامترها نیاز دارند:

| پارامتر | مقدار |
|---|---|
| `api_key` | کلید عمومی |
| `signature_method` | `HmacSHA256` یا `RSA` |
| `timestamp` | زمان جاری (میلی‌ثانیه) |
| `echostr` | رشته تصادفی ۳۰ تا ۴۰ کاراکتری |
| `sign` | امضا |

مراحل ساخت امضا:

۱. همه پارامترها را بر پایه نام کلید **الفبایی** مرتب کنید
۲. به شکل `key1=value1&key2=value2` به هم بچسبانید
۳. از رشته حاصل `MD5` بگیرید و **با حروف بزرگ** بنویسید
۴. نتیجه را با `HmacSHA256` و کلید محرمانه امضا کنید

نقاط پایانی خصوصی: `user_info.do`، `orders_info.do`، `orders_info_history.do`.

---

## کدهای خطا

| کد | معنا |
|---|---|
| `10000` | پارامتر نامعتبر (مثلاً تایم‌فریم پشتیبانی‌نشده) |
| `10002` | خطای داخلی سرور |
| `10003` | پارامتر ناقص |
| `10004` | امضای نامعتبر |
| `10005` | کلید API نامعتبر |
| `10006` | درخواست منقضی شده (اختلاف زمان) |
| `10008` | جفت‌ارز پشتیبانی نمی‌شود |
| `10014` | موجودی ناکافی |
| `10016` | موجودی ناکافی برای سفارش |
| `10022` | فراتر رفتن از محدودیت نرخ |

برنامه این کدها را به پیام‌های قابل فهم و ترجمه‌شده تبدیل می‌کند (`user_key`).

## محدودیت نرخ

LBank سقف دقیقی اعلام نکرده است. برنامه به‌صورت محافظه‌کارانه:

- حداکثر **۱۰ درخواست در ثانیه**
- تلاش مجدد با تأخیر نمایی روی خطاهای موقت
- کش حافظه‌ای با TTL تا درخواست‌های تکراری اصلاً ارسال نشوند

## آزمایش دستی

</div>

```bash
# زمان سرور
curl 'https://api.lbkex.com/v2/timestamp.do'

# قیمت بیت‌کوین
curl 'https://api.lbkex.com/v2/ticker/24hr.do?symbol=btc_usdt'

# ۵ کندل ساعتی
curl 'https://api.lbkex.com/v2/kline.do?symbol=btc_usdt&size=5&type=hour1&time=1757200000'

# اثبات پشتیبانی‌نشدن hour2
curl 'https://api.lbkex.com/v2/kline.do?symbol=btc_usdt&size=5&type=hour2&time=1757200000'
# → {"result":"false","error_code":10000, ...}
```

## خلاصه نکات کلیدی

۱. خطاها با HTTP 200 می‌آیند — حتماً `result` و `error_code` را بررسی کنید
۲. `result` هم رشته و هم بولی می‌شود
۳. `size` در `kline.do` رو به **جلو** می‌شمارد
۴. `time` بر حسب **ثانیه** است، ولی `timestamp` در پاسخ‌ها **میلی‌ثانیه**
۵. پنج تایم‌فریم پشتیبانی نمی‌شوند و باید تجمیع شوند
۶. پاسخ `ping` در WebSocket اجباری است
۷. پس از اتصال مجدد، اشتراک‌ها را دوباره برقرار کنید
