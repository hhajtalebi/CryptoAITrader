# تحویل نسخهٔ ۲.۲.۲ — رفع سه ایراد و درگاه دانلود

تاریخ: **۲۰۲۶-۰۹-۲۳** · پایهٔ توسعه: **2.2.1** (تغییرهای commit‌نشدهٔ همین جلسه)

نام بسته: `CryptoAITrader-v2.2.2-2026-09-23.zip`

**بدون commit/push/PR/انتشار GitHub؛ منتظر آزمون و دستور صریح مالک پروژه.**
این ZIP سورس است؛ EXE/APK جدید ساخته نشده و معاملهٔ واقعی فعال نشده است.

## اصلاح‌ها

### R1 — کش پیش‌بینی

`signals/prediction/engine.py::assess` دیگر هنگام ثبت گزارش تازه از `cached[0]`
استفاده نمی‌کند. نتیجهٔ جدید با یک timestamp مشترک در کش کلید تایم‌فریم و
نمای آخرین گزارش نماد ثبت می‌شود. درخواست یک نماد با دو tuple تایم‌فریم
مختلف، force refresh و انقضای TTL آزمون دارند. خواندن گزارش قدیمی از کش
هم آخرین گزارش ساخته‌شده را عقب نمی‌برد.

### R2 — انتقال تنظیم‌ها به موتور معامله

`ScalpService.build_trader_config()` اکنون همهٔ **۲۸ فیلد** AutoTradeConfig را
از تنظیم‌های متناظر می‌خواند؛ شامل engine_mode، نمادهای انتخابی، فاصلهٔ پویش،
نقدینگی، اسپرد، سن داده، لغزش، break-even، trailing، ابطال سیگنال، سیاست
تضاد روند و تخصیص سرمایه. مقدار صفر کارمزد/لغزش و False حفظ می‌شود؛ رشتهٔ
`false` به‌اشتباه True نمی‌شود. هیچ تنظیم ذخیره‌شده‌ای بازنویسی نمی‌شود.

در `AutoTrader.attach_tick_engine/apply_config` سن مجاز داده با cache متصل
همگام می‌شود تا ذخیرهٔ تنظیم فقط config را عوض نکند و STALE روی عدد قدیمی
نماند. تست DB → SettingsService → builder → موتور و تست محافظ اسپرد داریم.
تست واقعی متد `MainController.save_auto_trade_settings` نیز اضافه شده، اما
در این محیط به‌علت کتابخانه‌های Qt اجرا نشده است.

سقف‌های سخت موجود (اهرم/همزمانی/...) و شرط تأیید live حفظ شده‌اند؛ executor
واقعی همچنان وصل نیست. این اصلاح تأیید ایمنی معامله با پول واقعی نیست.

### R3 — برچسب صادقانهٔ پشتیبان؛ بدون حذف کلید

سیاست این وصله **حفظ داده و اصلاح manifest** است، نه پاک‌کردن انبار رمز:

- snapshot واقعی DB بررسی می‌شود، نه صرفاً تنظیم backend فعال.
- وجود رکورد `security.encrypted_secrets` حتی اگر خالی/ناخوانا باشد،
  `contains_encrypted_db_secrets=true` و `contains_secrets=true` می‌دهد.
- وجود فایل قدیمی settings.json، به دلیل نداشتن schema قابل اعتماد،
  `contains_uninspected_settings=true` و پرچم حساسیت را روشن می‌کند.
- خطای خواندن snapshot باعث شکست ساخت می‌شود؛ به‌عنوان «بدون راز» پنهان نمی‌شود.
- DB اصلی و ciphertext آن تغییر نمی‌کنند. hash بسته و صحت backup همچنان
  بررسی می‌شود؛ بازیابی مقدار ساختگی کلید در تست manual/pre_migration/
  pre_restore آزموده شد. DB قدیمی بدون جدول settings هم پشتیبان می‌گیرد.
- فایل‌های قدیمی backup بازنویسی نمی‌شوند؛ manifest قدیمی همچنان ممکن است
  غلط باشد. آن‌ها را خصوصی نگه دارید. تغییر روش مشتق‌سازی کلید رمزنگاری
  (R4) جزو این مرحله نیست.

**هر backup شخصی را خصوصی نگه دارید.** false بودن پرچم API keys به معنی
نداشتن سایر داده‌های خصوصی مثل حساب، مکالمه، معاملات یا نشست نیست.

## صفحهٔ دانلود محلی

`tools/serve_downloads.py` و `tools/download_page.html` یک درگاه مستقل، فارسی،
راست‌به‌چپ و سازگار با نمایشگر کوچک هستند. وابستگی آن فقط کتابخانهٔ استاندارد
Python 3.11+ است؛ به دیتابیس/کلید/سرویس معاملاتی برنامه متصل نمی‌شوند.

قابلیت‌ها:

- دکمهٔ دانلود ZIP با نام نسخه‌دار و Content-Disposition صحیح؛ GET و HEAD.
- نمایش اندازه، تعداد فایل، تغییرها، نتیجهٔ آزمون و SHA-256.
- دانلود SHA256SUMS.txt و نمایش release.json عمومی.
- بررسی اندازه و SHA-256 ZIP پیش از شروع سرور؛ رد مسیر بیرون پوشه یا symlink.
- مسیرهای ثابت و محدود: `/`، `/index.html`، `/download.zip`،
  `/SHA256SUMS.txt`، `/release.json` و `/font.ttf`.
- بدون directory listing و بدون ارائهٔ فایل دلخواه از مخزن. درخواست `.env`،
  `.git/config`، دیتابیس و path traversal پاسخ ۴۰۴ می‌گیرد.
- لینک‌های مرورگر نسبی‌اند؛ سرور روی `0.0.0.0` گوش می‌دهد و host پیش‌نمایش
  پذیرفته می‌شود. این درگاه احراز هویت ندارد؛ فقط سورسِ مورد تأیید برای
  تحویل را در پوشهٔ delivery بگذارید، نه backup یا اطلاعات شخصی.

### اجرای دوباره روی دستگاه خودتان

در یک پوشهٔ مجزا، ZIP دانلودشده و `release.json` دریافت‌شده از همین صفحه را
کنار هم بگذارید؛ فایل ZIP را بعد از محاسبهٔ hash عوض نکنید. سپس از ریشهٔ سورس:

```bash
python tools/serve_downloads.py --directory /path/to/delivery --port 8080
```

در ویندوز مسیر نمونه: `--directory C:\CryptoAITrader-delivery`.
روی همان دستگاه می‌توانید آدرس `http://localhost:8080` را باز کنید؛ برای
محیط Arena از کارت **صفحهٔ دانلود پروژه** در پیش‌نمایش زنده استفاده کنید،
نه localhost دستگاه شما. این سرور برنامهٔ دسکتاپ را اجرا نمی‌کند.

برای ساخت manifest محلی، نام ZIP واقعی را در نمونهٔ زیر جایگزین کنید:

```python
import hashlib, json, zipfile
from pathlib import Path
archive = Path("/path/to/delivery/CryptoAITrader-v2.2.2-2026-09-23.zip")
with archive.open("rb") as handle:
    digest = hashlib.file_digest(handle, "sha256").hexdigest()
with zipfile.ZipFile(archive) as package:
    count = len([name for name in package.namelist() if not name.endswith("/")])
manifest = {
    "version": "2.2.2", "filename": archive.name, "sha256": digest,
    "size_bytes": archive.stat().st_size, "file_count": count,
    "date": "2026-09-23", "tests": "708 passed / 3 skipped (core subset)",
}
archive.with_name("release.json").write_text(
    json.dumps(manifest, ensure_ascii=False, indent=2), encoding="utf-8"
)
```

ZIP خودش داخل ZIP قرار نمی‌گیرد. manifest و checksum کنار بستهٔ نهایی
نگهداری می‌شوند تا مشکل hash خودارجاعی ایجاد نشود.

## آزمون‌ها و محدودیت‌ها

- پیش از اصلاح محصول، ۱۸ تست اولیهٔ رگرسیون: **۱۲ شکست، ۶ موفق**؛ باگ‌ها
  واقعاً توسط تست گرفته شدند. سپس پوشش خطای خواندن backup و رکورد تهی افزوده شد.
- آزمون‌های جدید: **۲۰ رگرسیون هسته + ۱۴ تست درگاه دانلود** موفق؛
  **۱ تست سیم‌کشی Qt** به علت نبود کتابخانه‌های سیستمی skip.
- اجرای ترکیبی با همان ۳۳ فایل هستهٔ مرحلهٔ قبل: **۷۰۸ پاس، ۳ skip، صفر شکست**
  در بازاجرای نهایی ۲۶٫۷۴ ثانیه. دو skip دیگر LightGBM و PyTorch اختیاری نصب‌نشده‌اند.
- اجرای مجموعهٔ کامل باز هم در collection با ۳۰ ImportError مربوط به
  `libGL.so.1` متوقف شد. تست کامل GUI، نصب ویندوز و اتصال زندهٔ صرافی/AI
  در این محیط تأیید نشده‌اند. عددهای تاریخی README نتیجهٔ این مرحله نیستند.
- کنترل syntax، JSON، نسخه‌ها، CRLF فایل‌های BAT و `git diff --check` انجام می‌شود.
- ZIP شامل فایل‌های جدید commit‌نشده نیز هست؛ همهٔ ورودی‌ها به‌صورت بایت و
  SHA-256 با سورس تحویل تطبیق داده می‌شوند و CRC بررسی می‌شود.

آزمون‌های جدید به‌تنهایی:

```bash
QT_QPA_PLATFORM=offscreen CAT_DATA_DIR=/path/to/temporary-data \
python -m pytest tests/test_v222_review_fixes.py tests/test_v222_config_ui.py \
  tests/test_download_server.py -o addopts='' -q -ra
```

در ویندوز متغیر محیطی را با دستور مناسب PowerShell/CMD تنظیم کنید.
دستور اجرای کامل: `python -m pytest tests -q`؛ نیازمند Qt و کتابخانه‌های
سیستمی مربوط است.

## چک‌لیست پیشنهادی برای تست شما

۱. ZIP را در پوشه‌ای جدا استخراج کنید؛ قبل از جایگزینی نصب قبلی backup بگیرید.
۲. برای یک نماد، صفحهٔ پیش‌بینی و ترمینال را با تایم‌فریم متفاوت بررسی کنید.
۳. در حالت **paper** تنظیم اسپرد/نماد/تریلینگ/سقف مارجین را ذخیره و عملکرد
   موتور را بررسی کنید. سفارش واقعی آزمایش نشود.
۴. یک backup شخصی بسازید و در manifest پرچم‌های جدید را ببینید؛ فایل را
   در گفتگو/گیت‌هاب عمومی نگذارید. اگر DB کلید دارد باید حساس علامت بخورد.
۵. پس از اعلام نتیجه و تأیید، در صورت تمایل دستور صریح commit/push بدهید.
