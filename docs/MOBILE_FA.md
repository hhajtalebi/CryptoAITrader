# نسخهٔ موبایل و ربات ساخت APK

## خلاصه

نسخهٔ موبایل یک برنامهٔ **مستقل اندروید** است. روی گوشی اجرا می‌شود،
خودش داده می‌گیرد و خودش تحلیل می‌کند. به کامپیوتر، سرور یا وای‌فای
خانه نیازی ندارد.

```
scripts\build_apk.bat
```

---

## یک تصمیم مهندسی که باید بدانید

رابط دسکتاپ با **PySide6 (Qt)** نوشته شده. Qt for Python روی اندروید
بسته‌بندی رسمی و پایداری ندارد. بنابراین:

| بخش | وضعیت |
|-----|--------|
| **موتور تحلیل** | همان منطق، بازنویسی بدون pandas — **هم‌ارزی عددی آزمون دارد** |
| **رابط کاربری** | با Kivy از نو نوشته شد (تنها مسیر آزموده‌شدهٔ APK پایتونی) |
| **کلید API و معاملهٔ واقعی** | عمداً حذف شد |

### چرا pandas روی موبایل نیست

pandas یکی از بدنام‌ترین بسته‌ها برای کامپایل روی اندروید است. حتی
وقتی APK ساخته می‌شود، اپ اغلب هنگام `import` با خطای پیوند بسته
می‌شود.

راه سالم، حذف وابستگی بود نه جنگیدن با آن. `mobile/app/indicators_lite.py`
همان فرمول‌ها را با پایتون خالص پیاده می‌کند.

**و این ادعا آزمون دارد.** `tests/test_v1912_mobile.py` خروجی هر
اندیکاتور را با همان محاسبهٔ pandas مقایسه می‌کند و اختلاف بیش از
`1e-9` را شکست می‌شمارد:

```
ema  sma  rsi  macd  macd.signal  atr  bollinger   →  ۰ اختلاف
```

اگر روزی یکی از دو طرف تغییر کند، آزمون می‌شکند — نه کاربر.

### چرا کلید API روی گوشی نیست

گوشی گم می‌شود و دزدیده می‌شود. نگه‌داشتن کلید صرافی رویش ریسکی است
که ارزشش را ندارد. نسخهٔ موبایل فقط از نقاط پایانی **عمومی** می‌خواند.
معامله روی نسخهٔ دسکتاپ می‌ماند.

## ساخت APK

### پیش‌نیاز: WSL

**buildozer روی خود ویندوز اجرا نمی‌شود.** زنجیرهٔ ساخت اندروید به
ابزارهای POSIX نیاز دارد. راه رسمی، WSL است.

در PowerShell **با دسترسی مدیر**:

```powershell
wsl --install -d Ubuntu
```

ویندوز را ری‌استارت کنید. سپس یک بار داخل WSL:

```bash
sudo apt update
sudo apt install -y python3-pip openjdk-17-jdk zip unzip autoconf libtool \
     pkg-config zlib1g-dev libncurses-dev cmake libffi-dev libssl-dev git
pip3 install --user buildozer cython
```

> Android Studio که دارید مفید است، اما buildozer خودش SDK و NDK لازم
> را دانلود می‌کند. نیازی به تنظیم دستی نیست.

### اجرا

```bat
scripts\build_apk.bat
```

ربات این‌ها را انجام می‌دهد:

| گام | کار |
|-----|------|
| ۱ | تشخیص محیط؛ روی ویندوز فرمان را داخل WSL می‌برد |
| ۲ | **آزمون هم‌ارزی ریاضی** — با شکست، ساخت متوقف می‌شود |
| ۳ | اجرای buildozer |
| ۴ | کپی APK در `dist\apk\` |

> **اولین ساخت ۴۰ تا ۹۰ دقیقه** طول می‌کشد چون NDK و SDK دانلود
> می‌شوند (چند گیگابایت). ساخت‌های بعدی چند دقیقه‌اند.

گزینه‌ها:

```bat
scripts\build_apk.bat --release      REM نسخهٔ انتشار
scripts\build_apk.bat --clean        REM پاک‌سازی ساخت قبلی
```

### نصب روی گوشی

۱. `dist\apk\*.apk` را به گوشی منتقل کنید
۲. «نصب از منابع ناشناس» را برای فایل‌منیجر فعال کنید
۳. روی فایل بزنید

## امکانات نسخهٔ موبایل

* تحلیل تک‌نماد در چهار تایم‌فریم (۱۵m، ۱h، ۴h، ۱d)
* پویش همهٔ نمادها با مرتب‌سازی بر پایهٔ اطمینان
* هر سیگنال: جهت، محدودهٔ ورود، حد ضرر، سه هدف، نسبت سود به زیان،
  **مدت اعتبار**، و دلیل‌های تصمیم
* «منتظر» یک نتیجهٔ درجه‌یک است — با دادهٔ ناکافی هرگز سیگنال ساختگی
  نمی‌سازد
* رابط فارسی راست‌به‌چپ با تم سرمه‌ای اداری
* رنگ‌بندی: سبز خرید، قرمز فروش، کهربایی منتظر

## عیب‌یابی

| نشانه | چاره |
|-------|------|
| «WSL در دسترس نیست» | `wsl --install -d Ubuntu` سپس ری‌استارت |
| `buildozer: command not found` | `pip3 install --user buildozer` داخل WSL |
| ساخت در NDK می‌ایستد | اینترنت را بررسی کنید؛ `--clean` بزنید |
| اپ روی گوشی باز و بسته می‌شود | `adb logcat | grep python` برای دیدن خطا |
| متن فارسی به هم ریخته | `Vazirmatn-Regular.ttf` را در `mobile/assets/` بگذارید |
