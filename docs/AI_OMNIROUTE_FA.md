# دروازهٔ هوش مصنوعی OmniRoute

این سند توضیح می‌دهد OmniRoute چیست، چرا به برنامه اضافه شد، چطور راهش
بیندازید و در کجای معماری می‌نشیند.

---

## ۱) OmniRoute چیست؟

یک **دروازه (Gateway)** متن‌باز است که روی دستگاه خودتان اجرا می‌شود و
ده‌ها سرویس هوش مصنوعی را پشت **یک نشانی سازگار با OpenAI** جمع می‌کند.

بدون دروازه:

```
برنامه ──► OpenAI        (کلید ۱)
برنامه ──► OpenRouter    (کلید ۲)
برنامه ──► Groq          (کلید ۳)
```

با دروازه:

```
برنامه ──► OmniRoute ──┬─► OpenAI
  (یک نشانی،           ├─► OpenRouter
   یک کلید)            ├─► Groq
                       └─► مدل محلی (Ollama / LM Studio)
```

سود عملی برای شما:

1. **کلیدها یک‌جا جمع می‌شوند.** کلید هر سرویس را یک بار داخل خود دروازه
   می‌گذارید و در برنامه فقط یک نشانی می‌دهید.
2. **جایگزینی خودکار.** اگر سهمیهٔ یک سرویس تمام شود، دروازه خودش سراغ
   سرویس بعدی می‌رود و گفتگو قطع نمی‌شود.
3. **مدل‌های رایگان.** دروازه سرویس‌های بدون‌کلید (مثل Pollinations) را هم
   می‌شناسد، پس می‌توان بدون هیچ هزینه‌ای شروع کرد.

> **توجه:** OmniRoute خودش مدلی ندارد؛ فقط مسیریاب است. هر مدلی که
> می‌بینید از یک سرویس بالادستی می‌آید.

---

## ۲) راه‌اندازی در سه گام

### گام ۱ — نصب و اجرای دروازه

نیازمندی: Node.js نسخهٔ ۲۲ یا بالاتر.

```bash
npm install -g omniroute
omniroute
```

دروازه روی **پورت ۲۰۱۲۸** بالا می‌آید و داشبوردش در مرورگر باز می‌شود.

### گام ۲ — اتصال سرویس‌ها (اختیاری)

در داشبورد به **Providers** بروید و سرویس‌هایتان را وصل کنید. اگر این گام
را رد کنید هم دروازه کار می‌کند: نصب تازه از پیش به چند سرویس رایگانِ
بدون‌کلید وصل است.

### گام ۳ — انتخاب در برنامه

در برنامه به **تنظیمات ← هوش مصنوعی** بروید:

| کادر            | مقدار                                                    |
| --------------- | -------------------------------------------------------- |
| سرویس           | `OmniRoute (دروازه چندسرویسی)`                            |
| نشانی           | `http://localhost:20128/v1` (خودکار پر می‌شود)            |
| مدل             | `auto` (پیشنهاد می‌شود)                                    |
| کلید            | فقط اگر روی دروازه احراز هویت را روشن کرده‌اید             |

سپس **«آزمایش اتصال»** را بزنید.

---

## ۳) دربارهٔ کلید API

کلید در OmniRoute **اختیاری** است و این تفاوت مهمی با بقیهٔ سرویس‌هاست:

- نصب تازهٔ دروازه (`REQUIRE_API_KEY=false` که پیش‌فرض است) **بدون کلید**
  پاسخ می‌دهد.
- اگر `REQUIRE_API_KEY=true` را روشن کرده باشید، باید در داشبورد به
  **Endpoints** بروید، یک کلید بسازید و همان را در برنامه وارد کنید.

به همین دلیل کادر کلید برای این سرویس **فعال می‌ماند** حتی با آنکه
«اجباری» علامت نخورده است. در کد این تمایز با دو فیلد جدا بیان شده:

```python
requires_key = False          # بدون کلید هم کار می‌کند
accepts_optional_key = True   # ولی کلید را می‌پذیرد ⇒ کادر باز بماند
```

**امنیت:** کلید دقیقاً مثل کلید صرافی‌ها رمزنگاری‌شده در پایگاه‌داده ذخیره
می‌شود، فقط در سرآیند `Authorization` می‌رود، و هرگز در لاگ، پیام خطا یا
خروجی ابزارها ظاهر نمی‌شود.

## ۴) نام‌گذاری مدل‌ها

مدل‌های دروازه پیشوند سرویس دارند:

| شناسهٔ مدل             | یعنی                         |
| ---------------------- | ---------------------------- |
| `auto`                 | انتخاب با خود دروازه          |
| `gg/gemini-2.5-pro`    | Gemini                        |
| `if/kimi-k2-thinking`  | iFlow                         |
| `cc/claude-opus-4-6`   | Claude Code                   |
| `groq/llama-3.3-70b`   | Groq                          |
| `glm/glm-4.7`          | GLM / ژیپو                    |

برنامه این پیشوندها را به نام خوانا ترجمه می‌کند
(`ai/providers/omniroute_provider.py::PROVIDER_PREFIXES`). پیشوند
ناشناخته **حذف نمی‌شود**؛ خودِ پیشوند نشان داده می‌شود، چون دروازه مدام
سرویس تازه اضافه می‌کند و برنامه نباید هر بار بشکند.

### چرا `auto` بالای فهرست است؟

برای کاربری که تازه وصل شده، سپردن انتخاب به دروازه امن‌ترین گزینه است و
نیازی به دانستن پیشوندها ندارد. دروازه `auto` را به یک مدل واقعی حل
می‌کند و همان نام واقعی را در پاسخ برمی‌گرداند.

## ۵) ابزارهای تازهٔ عامل هوش مصنوعی

دو ابزار به جعبه‌ابزار عامل اضافه شده تا بتوان **در خود گفتگو** دربارهٔ
دروازه پرسید:

| ابزار               | چه می‌کند                                               |
| ------------------- | ------------------------------------------------------- |
| `omniroute_status`  | دروازه در دسترس است؟ کدام مدل فعال است؟ چند مدل دارد؟    |
| `omniroute_models`  | فهرست مدل‌ها، گروه‌بندی‌شده بر پایهٔ سرویس، با امکان فیلتر |

نمونه پرسش‌هایی که حالا جواب واقعی می‌گیرند:

> «الان به چه مدلی وصلم؟»
> «چه مدل‌هایی از Gemini در دسترس دارم؟»

**قاعدهٔ ضدتوهم:** اگر دروازه در دسترس نباشد، ابزار صریحاً شکست را گزارش
می‌دهد تا مدل بگوید «نمی‌دانم» — نه اینکه فهرستی از خودش بسازد. همین
موضوع باعث شد تشخیص «دروازه خاموش است» از «دروازه هیچ مدلی ندارد» با
پرچم `last_listing_ok` جدا شود.

## ۶) جای دروازه در معماری

```
                       ┌──────────────────────────┐
                       │      Application          │
                       │  (ریشهٔ ترکیب وابستگی‌ها)   │
                       └────────────┬─────────────┘
                                    │
         ┌──────────────────────────┼──────────────────────────┐
         ▼                          ▼                          ▼
  AIProviderManager          CompositeToolset            SecretStore
         │                          │                    (کلید رمزنگاری‌شده)
         │                 ┌────────┴────────┐
         ▼                 ▼                 ▼
  OmniRouteProvider   MarketToolset   OmniRouteToolset
         │
         ▼
  http://localhost:20128/v1
```

نکته‌های معماری:

- `OmniRouteProvider` از `OpenAICompatibleProvider` ارث می‌برد؛ فقط چهار
  تفاوت رفتاری را بازنویسی می‌کند (نشانی پیش‌فرض، سرآیند شناسایی، پیام
  خطای ۴۰۱، و اولویت `auto`).
- `CompositeToolset` ابزار بازار و ابزار دروازه را کنار هم می‌گذارد تا
  عامل‌ها یک جعبه‌ابزار واحد ببینند. افزودن خانوادهٔ ابزار تازه دیگر نیازی
  به تغییر عامل‌ها ندارد.
- ابزارهای دروازه **همیشه** ثبت می‌شوند، حتی وقتی سرویس فعال OmniRoute
  نیست. در آن حالت ابزار صادقانه می‌گوید «پیکربندی نشده» و کاربر می‌فهمد
  چرا؛ مخفی‌کردنشان فقط پرسش «چرا جواب نمی‌دهد؟» می‌ساخت.

## ۷) عیب‌یابی

| نشانه                                            | علت و راه‌حل                                                        |
| ------------------------------------------------ | ------------------------------------------------------------------- |
| «دروازه در دسترس نیست … با فرمان omniroute اجرا کنید» | دروازه بالا نیامده. در ترمینال `omniroute` را اجرا کنید.       |
| «کلید را رد کرد … Dashboard ← Endpoints»          | روی دروازه `REQUIRE_API_KEY` روشن است. کلید بسازید و وارد کنید.      |
| فهرست مدل خالی است                                | هنوز هیچ سرویسی در داشبورد وصل نشده. یک سرویس (حتی رایگان) وصل کنید. |
| پورت ۲۰۱۲۸ اشغال است                              | با `PORT=…` پورت دیگری بدهید و همان نشانی را در برنامه بگذارید.      |

## ۸) افزودن سرویس مشابه در آینده

اگر دروازهٔ دیگری (مثلاً AgentRouter) بخواهید، معمولاً **یک ردیف** در
`ai/providers/catalog.py` کافی است:

```python
ProviderPreset(
    key="agentrouter",
    display_name="AgentRouter",
    provider_type="openai_compatible",
    base_url="https://agentrouter.org/v1",
    requires_key=True,
)
```

کلاس جدا فقط وقتی لازم است که سرویس **رفتار متفاوتی** داشته باشد — مثل
همین چهار مورد OmniRoute. راهنمای کامل: `docs/ADD_AI_PROVIDER_FA.md`.
