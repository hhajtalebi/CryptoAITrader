## تصمیم‌های کلیدی

### ۱. ریشه ترکیب واحد (`Application`)

همه وابستگی‌ها در `app/application.py` ساخته و به هم وصل می‌شوند. هیچ کلاسی وابستگی‌هایش را خودش نمی‌سازد.

</div>

```python
# ✅ درست — وابستگی تزریق می‌شود
class SignalEngine:
    def __init__(self, market: MarketDataEngine, indicators: IndicatorEngine, risk: RiskEngine):
        self._market = market

# ❌ غلط — کلاس به پیاده‌سازی مشخصی گره می‌خورد و آزمون‌ناپذیر می‌شود
class SignalEngine:
    def __init__(self):
        self._market = MarketDataEngine(LBankProvider())
```

<div dir="rtl">

**سود عملی:** در آزمون‌ها یک `FakeMarketEngine` جای موتور واقعی می‌نشیند و کل موتور سیگنال بدون شبکه آزمایش می‌شود.

### ۲. رجیستری‌ها بدون عارضه جانبی هنگام import

اندیکاتورها، استراتژی‌ها، صرافی‌ها و ارائه‌دهنده‌های هوش مصنوعی همه در رجیستری ثبت می‌شوند، اما ثبت **خودکار نیست**:

</div>

```python
# در Application.__init__
register_builtin_providers()
register_builtin_indicators()
register_builtin_strategies()
```

<div dir="rtl">

**چرا؟** اگر `import indicators` به‌خودی‌خود چیزی را ثبت کند، ترتیب import اهمیت پیدا می‌کند و اشکال‌های مرموزی می‌سازد. با ثبت صریح، همیشه معلوم است چه‌وقت و چه چیزی ثبت شده.

> ⚠ نتیجه عملی: رجیستری‌ها **هنگام import خالی‌اند**. هر آزمونی که مستقیم با آن‌ها کار می‌کند باید خودش تابع ثبت را صدا بزند.

### ۳. موتور سیگنال از هوش مصنوعی مستقل است

</div>

```
سیگنال کامل بدون هوش مصنوعی ساخته می‌شود
                  ↓
    enrich_with_ai() فقط این‌ها را می‌افزاید:
        analysis_text, ai_provider, ai_model
                  ↓
    قیمت‌ها، جهت و ریسک هرگز تغییر نمی‌کنند
```

<div dir="rtl">

**چرا؟** مدل زبانی ممکن است خطا کند یا در دسترس نباشد. اگر سیگنال به آن وابسته باشد، برنامه بدون اینترنت یا بدون مدل بی‌فایده می‌شود. این جدایی با آزمون تضمین شده است.

### ۴. `WAIT` یک خروجی درجه‌یک است

بیشتر اوقات بازار ستاپ روشنی ندارد. برنامه‌ای که همیشه سیگنال می‌دهد، در حال حدس زدن است. `WAIT` هم دلیل دارد و هم ذخیره می‌شود.

### ۵. «اطمینان» برچسب صادقانه دارد

عدد اطمینان از هم‌جهت بودن عوامل محاسبه می‌شود:

</div>

```
alignment = 0.6 × |score| + 0.4 × consensus
```

<div dir="rtl">

این **احتمال سود نیست** و در رابط کاربری، گزارش‌ها و مستندات صریحاً همین‌طور برچسب خورده است. ادعای نرخ برد بدون معامله واقعی، فریب کاربر است — به همین دلیل در خلاصه گزارش‌ها هیچ فیلد «نرخ برد» وجود ندارد (آزمون خودکار دارد).

### ۶. حالت آفلاین یک قابلیت است، نه خطا

</div>

```
درخواست کندل
     ↓
کش حافظه (TTL)  → موجود؟ برگردان
     ↓
REST صرافی      → موفق؟ ذخیره در پایگاه داده و برگردان
     ↓
پایگاه داده     → داده قدیمی موجود؟ با هشدار برگردان
     ↓
InsufficientDataError با پیام قابل ترجمه
```

<div dir="rtl">

قطع اینترنت هرگز نباید برنامه را ببندد.

### ۷. رابط گرافیکی هرگز نباید یخ بزند

موتورها ناهمگام (`async`) هستند و Qt همگام. پل میان این دو `AsyncRunner` است: یک حلقه رویداد asyncio روی نخ جداگانه، که نتیجه را با سیگنال‌های Qt به نخ رابط کاربری برمی‌گرداند.

</div>

```python
self.runner.submit(
    "analysis",
    self.app.market.get_candles(symbol, timeframe),
    on_success=self._show_candles,
    on_error=self._show_error,
)
```

<div dir="rtl">

**قاعده مطلق:** هیچ ویجتی از نخ پس‌زمینه دست‌کاری نمی‌شود. اتصال سیگنال میان‌نخی در Qt خودکار صف‌بندی می‌شود و همین تنها راه امن است.

### ۸. رشته‌های رابط کاربری هرگز در کد نیستند

</div>

```python
# ✅ درست
self.run_button.setText(self.tr_.tr("analysis.run"))

# ❌ غلط
self.run_button.setText("اجرای تحلیل")
```

<div dir="rtl">

هر صفحه یک متد `retranslate()` دارد که با تغییر زبان، بدون ساخت دوباره ویجت‌ها فراخوانی می‌شود. آزمون خودکار بررسی می‌کند که هیچ کلیدی بین فارسی و انگلیسی جا نیفتاده باشد.

### ۹. رمزها هرگز کنار داده نمی‌نشینند

| کجا | چه چیزی |
|---|---|
| SQLite | فقط پرچم `has_credentials` |
| Windows Credential Manager | خود کلیدها |
| فایل رمزنگاری‌شده | جایگزین وقتی keyring نیست |
| لاگ‌ها | هیچ — `SensitiveDataFilter` ماسک می‌کند |
| پشتیبان‌ها | هیچ — آزمون خودکار دارد |

### ۱۰. خطاها معنا دارند

همه خطاها از `AppError` ارث می‌برند و سه چیز دارند: `message` (برای توسعه‌دهنده)، `user_key` (کلید ترجمه برای کاربر)، `details` (زمینه برای عیب‌یابی).

</div>

```python
raise InsufficientDataError(
    f"Only {len(candles)} candles for {symbol} {timeframe}",
    user_key="errors.insufficient_data",
    details={"symbol": symbol, "timeframe": timeframe, "count": len(candles)},
)
```

## جریان یک سیگنال، از ابتدا تا انتها

</div>

```
کاربر روی «تولید سیگنال» کلیک می‌کند
        ↓
MainController.generate_signal()          نخ رابط کاربری
        ↓
AsyncRunner.submit(...)                   → نخ پس‌زمینه
        ↓
Application.generate_signal(symbol)
        ↓
SignalEngine.generate()
        ├─→ MarketDataEngine.get_multi_timeframe_candles()
        │       └─→ کش → REST → پایگاه داده
        ├─→ IndicatorEngine.calculate_many()          ۲۴ اندیکاتور
        ├─→ analyze_market_structure()                 روند و ساختار
        ├─→ استراتژی‌ها رأی می‌دهند                     ۳ استراتژی
        ├─→ رأی‌ها با وزن تایم‌فریم ترکیب می‌شوند
        ├─→ RiskEngine.calculate_stop_loss()
        ├─→ RiskEngine.assess()                        ممکن است رد کند
        └─→ TradingSignal ساخته می‌شود
        ↓
(اختیاری) AIAnalyst.enrich_with_ai()       فقط متن
        ↓
SignalRepository.save_signal()
        ↓
سیگنال Qt  →  نخ رابط کاربری  →  SignalsPage.show_signal()
```

## نقشه پوشه‌ها

| پوشه | مسئولیت | به چه چیزی وابسته است |
|---|---|---|
| `app/` | تنظیمات، پایگاه داده، امنیت، لاگ، خطاها | هیچ (پایه) |
| `market/` | داده بازار و صرافی‌ها | `app/` |
| `indicators/` | محاسبه اندیکاتور | `app/` |
| `signals/` | تولید سیگنال و ارزیابی ریسک | `app/`, `market/`, `indicators/` |
| `ai/` | تحلیل زبانی | `app/`, `market/`, `indicators/` |
| `reports/` | ساخت و خروجی گزارش | `app/` |
| `backup/` | پشتیبان‌گیری | `app/` |
| `localization/` | ترجمه‌ها | `app/` |
| `ui/` | رابط گرافیکی | همه لایه‌های بالا |
| `tests/` | ۹۲ آزمون | همه |

اگر روزی نیاز شد `market/` چیزی از `ui/` بداند، طراحی جایی اشتباه رفته است.
